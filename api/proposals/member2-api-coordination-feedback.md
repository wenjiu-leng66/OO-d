# 成员 2：API 协作反馈与待确认事项

本文对应成员 6 的 `docs/member6-rbac0-api` 分支草案，区分当前 Mock 实现、建议和待办，不表示团队已确认或真实接口已联调。最终接口以团队确认后的 [OpenAPI](../openapi.yaml) 为准。

## 1. 登录方式、会话失效与退出

Cookie 或 Bearer Token 前端都可以适配，需要统一确定。成员 6 当前草案采用 HttpOnly Cookie，尚待确认 Cookie 属性、会话有效期、CSRF 防护及开发代理或跨域配置。Cookie 接入不仅是添加请求凭据选项，还需要后端配合。

真实接口接入后，前端计划统一处理 401：清理身份和权限状态，跳转登录页；退出调用后端接口，由后端使会话失效。

当前只有 Mock 内存登录，没有正式 HTTP 客户端、Cookie、Token 或 401 拦截器。退出只清理 Mock 和 Vue 状态，刷新页面也会失去会话。

当前 Mock 只允许启用且拥有超级管理员或部门管理员角色的账号登录管理系统。普通员工不能登录；员工账号获得部门管理员角色后可以登录，判断不依赖岗位或账号类别。仅有业务角色的临时运维账号当前也会被拒绝，其最终管理系统登录资格待团队确认。本规则不代表禁止这些账号登录其他业务系统。

## 2. 用户角色分配权限码

同意统一使用 `rbac:user:assign-role` 控制角色分配与撤销，使用 `rbac:user:update` 控制账号启用与停用。

当前用户详情按钮和 Mock 保存校验已拆分，两类操作分别检查权限。超级管理员、部门管理员的演示角色已包含角色分配权限；部门范围和账号保护继续独立校验。

真实接口接入时，还需按契约携带用户角色集合版本，处理完整替换、版本冲突和保存失败；当前 `updateUserRoles()` 尚未实现版本参数。

## 3. 工作台访问和数据范围

工作台路由及侧边栏入口只要求登录，页面内部的统计和快捷入口分别检查权限。无统计权限时不显示统计，也不发送概览请求。

当前 Mock 已实现：

- 超级管理员查看全系统用户数、临时账号数和系统角色数。
- 部门管理员查看本部门用户数、临时账号数，以及本部门用户已分配角色的去重数量；该数量不是全系统角色目录数量，也不是可分配角色数量。
- 统计请求需要 `rbac:user:read`；添加账号快捷入口需要用户查看和创建权限，用户查询入口需要用户查看权限，组织入口需要部门查看权限。

真实统计接口和范围需写入契约，由后端执行范围过滤。

## 4. 角色、权限变化的生效时机

建议后端在授权变更成功后，对后续请求立即按新权限执行授权和数据范围检查，不要求用户重新登录。

后端接口确定后，前端计划在授权操作成功后及必要的路由跳转时重新获取有效权限，更新菜单和按钮；权限加载期间不放行需要权限的页面，失败时不继续依赖旧权限放行。

当前 Mock 修改角色权限后会重新计算 Mock 用户的有效权限，并提供 `getCurrentUser()`；Vue 会话仍保存登录时的权限快照，尚未自动刷新，没有实现路由跳转时请求 `/me/permissions`。

其他已登录会话的更新通知或查询机制、缓存失效和前端刷新策略需要共同确认。前端刷新不能代替后端即时撤权。

## 5. 越权目标返回 403 或 404

前端可以按最终契约处理两者。建议没有操作权限时返回 403；需要隐藏目标对象是否存在时，可统一返回 404，具体对象检查次序和防枚举策略由后端及成员 6 明确，两种后端保持一致。

当前 Vue 路由对无权限页面跳转 `/403`，未知地址显示 404 页面；Mock 只抛出错误消息，不返回正式 HTTP 状态或业务错误码。路由页面的 404 不等于已实现接口防枚举。

## 6. all、department、self 的含义及合并规则

请团队明确“全部、本部门、本人”的对象范围、本部门是否包含下级部门，以及不同资源中“本人”的具体含义。

建议对同一权限码下多个角色授予的数据范围取并集，不把某项操作的范围扩展到其他操作。

后端负责授权和过滤，成员 2负责让组织选择、筛选和展示符合返回范围。当前 Mock 仅支持超级管理员全局、部门管理员本部门用户，不包含正式 self 范围、下级部门扩展或多角色范围合并。

## 7. 自身账号、唯一超级管理员和内置角色保护

当前 Mock 已禁止：

- 停用当前登录账号。
- 修改当前登录账号的角色。
- 停用唯一超级管理员，或修改该账号的角色。
- 通过创建用户或角色分配授予超级管理员角色。
- 修改内置超级管理员角色的权限。

以上是当前原型规则，请团队逐项确认。禁止修改自身角色是额外业务约定，不是 RBAC0 的必然要求；其他内置角色是否受保护、保护哪些字段也需另行明确。

建议权限不足返回 403，违反业务保护规则返回 409，并提供稳定的业务错误码。前端应区分账号保护、角色保护和版本冲突，不能把所有 409 都显示为“无法停用账号”。当前 Mock 只有错误消息，尚未实现这些 HTTP 状态和错误码。
