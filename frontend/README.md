在 `frontend/` 目录执行：

```powershell
npm install
npm run dev
```

访问终端输出的地址，通常为：

```text
http://localhost:5173
```

### 演示账号

预置账号的演示密码均为 `123456`。

支持员工号或对应手机号登录，不支持用户名登录。

| 员工号 | 手机号 | 说明 |
| --- | --- | --- |
| E001 | 13800000001 | 唯一超级管理员，管理全部组织 |
| E002 | 13800000002 | 部门管理员，管理人力资源部账号 |
| E003 | 13800000003 | 已停用，不能登录 |
| E004 | 13800000004 | 普通员工，可以认证，但没有后台管理权限 |
| OPS001 | 13800000005 | 临时运维账号，当前角色没有后台管理权限 |

新建账号使用添加用户时填写的初始密码。

账号、密码、会话及修改结果只保存在本次页面运行内存中。刷新页面后恢复预置数据，需要重新登录。

不要在原型中输入真实员工个人信息或真实密码。正式密码哈希存储、认证和会话管理由后端实现。

### 用户、岗位与角色

| 概念 | 含义 | 示例 |
| --- | --- | --- |
| 账号类别 | 账号用途或人员来源 | 员工账号、临时运维账号 |
| 岗位 | 实际工作职位 | 人事专员、会计、工程师、部门经理 |
| 角色 | 决定权限的集合，可以多选 | 普通员工、部门管理员、公文查看员 |

添加用户时，公司、部门、岗位逐级联动：

```text
公司 → 部门 → 岗位
```

切换公司会清空部门和岗位，切换部门会清空岗位。

角色选择独立于岗位和账号类别，支持搜索和多选。岗位不会自动授予权限，账号类别也不会自动分配角色。

用户有效权限为已分配角色权限的去重并集。允许账号没有角色，此时不会自动获得权限。

用户列表不展开角色，完整角色和权限在详情页展示。

员工号和手机号必须唯一。前端表单和 mock API 提供重复校验；正式后端仍须通过数据库唯一约束保证唯一性。

### 管理范围

- 部门管理员是角色，可以与其他角色共存。
- 部门管理员只能查看、创建和维护本人所属部门账号。
- 超级管理员管理全部组织。
- 只保留一个预置超级管理员账号 E001。
- 新增用户的角色目录不提供超级管理员选项。
- mock API 拒绝创建第二个超级管理员。
- 不允许停用唯一超级管理员或当前登录账号。

这些是原型中的演示规则，正式后端必须再次验证。

### 状态验证

先使用 E001 登录，再在地址栏打开以下路径：

| 路径 | 预期状态 |
| --- | --- |
| `/users` | 正常用户列表 |
| `/users?demo=loading` | 骨架屏，约 1.8 秒后展示数据 |
| `/users?demo=empty` | 暂无匹配用户 |
| `/users?demo=error` | 用户加载失败及重新加载入口 |
| `/departments` | 正常组织树 |
| `/departments?demo=loading` | 部门加载中 |
