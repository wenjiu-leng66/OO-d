# 成员 2：前端数据与 API 契约草案

状态：前端第一阶段草案，供成员 3、4、6 评审。本文记录页面当前实现和接口需求，不替代 [`api/openapi.yaml`](../../api/openapi.yaml)。正式接口确认后，字段和状态码以 OpenAPI 为准。

## 1. 责任边界

成员 2 负责公共布局、登录、用户管理、部门架构、分页筛选和 API 客户端适配。角色权限、角色继承和约束页面由成员 3 接入公共框架。

页面只负责展示状态和提交用户操作；后端必须在每次请求中重新认证和授权，不能信任浏览器保存的权限列表。

新增用户的公司、部门和岗位采用联动选择；角色选择独立于组织、岗位和账号类型，从完整角色目录中搜索并多选。提交 `roleIds: string[]`，空数组表示未分配角色。角色名称及有效权限只在用户详情展示，不在用户列表展开。RBAC0 有效权限为所有已分配角色权限的去重并集；岗位名称不自动授予权限。当前目录为 mock 样例，正式目录以后端接口返回为准。

## 3. 分页约定

用户列表使用服务端分页作为正式接口目标，原型阶段使用同样的数据形状在前端切片。

| 项目 | 约定 |
| --- | --- |
| 页码 | `page` 从 1 开始 |
| 每页条数 | `pageSize`，默认 20，最大 100 |
| 返回列表 | `items: User[]` |
| 总数 | `total: number`，表示筛选后的总条数 |
| 翻页行为 | 页码改变时重新请求；筛选条件改变时回到第 1 页 |
| 空页 | 返回 `items: []` 时显示“暂无匹配用户”，不视为错误 |

建议请求示例：

```text
GET /api/v1/users?page=1&pageSize=20&keyword=张三&departmentId=dept-01
```

当前原型的 `UsersView.vue` 使用 `pageSize = 3` 便于演示分页；接入后端时改为接口返回分页结果。

## 4. 筛选和搜索

用户页支持姓名/工号关键词和部门筛选。关键词按包含关系匹配，正式接口是否区分大小写由后端统一决定。

| 条件 | 参数 | 行为 |
| --- | --- | --- |
| 姓名或工号 | `keyword` | 输入变化后重新查询 |
| 部门 | `departmentId` | 选择后重新查询 |
| 清除条件 | 参数不传 | 恢复全部可见用户 |
| 条件变化 | - | 页码重置为 1 |
| 无匹配 | - | 显示空数据状态 |

部门架构页面暂不提供搜索；后续部门数量较大时再增加名称搜索，并沿用同一状态和请求规则。

## 5. 数据字段

### 5.1 用户

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | `string` | 是 | 用户稳定 ID，前端路由和更新操作使用 |
| `name` | `string` | 是 | 展示姓名 |
| `employeeNo` | `string` | 是 | 员工/工号，业务唯一标识由后端保证 |
| `departmentId` | `string` | 是 | 所属部门 ID |
| `departmentName` | `string` | 是 | 列表展示用名称，可由接口展开返回 |
| `branch` | `string` | 是 | 分公司或组织主体 |
| `position` | `string` | 是 | 岗位名称 |
| `status` | `string` | 是 | `active` 或 `inactive` |
| `phone` | `string` | 否 | 联系电话，是否可见由后端权限决定 |
| `roles` | `string[]` | 否 | 当前分配的角色名称，用于详情展示 |
| `permissionCodes` | `string[]` | 否 | 当前有效权限摘要，最终以后端返回为准 |

### 5.2 部门

```js
{
  id: string,
  name: string,
  manager: string,
  branch: string,
  parentId: string | null,
  parentName: string | null,
  employeeCount: number,
  children: Department[]
}
```

`children` 只用于树形展示；部门归属和层级合法性由后端维护。前端不能根据名称自行推断父子关系。

组织目录采用固定层级表达：

```text
总公司
├─ 总公司直属部门
│  ├─ 办公室
│  ├─ 人力资源部
│  └─ 财务部
└─ 分公司
   └─ 分公司部门
      ├─ 综合办公室
      └─ 工程技术部
```

部门树节点需要显示组织类型（总公司、分公司、部门），选中节点时展示完整路径、负责人、上级组织、所属分公司和员工数量。

### 5.3 会话

```js
{
  isAuthenticated: true,
  user: {
    id: string,
    name: string,
    employeeNo: string,
    departmentName: string
  },
  permissionsLoaded: true,
  permissions: string[]
}
```

`permissions` 只用于菜单、路由和按钮展示；服务端授权不能依赖它。

## 6. API 客户端

页面通过 `src/api/` 统一调用接口，不在 `.vue` 文件中直接散落 `fetch`。当前 `src/api/mock.js` 是无后端时的临时适配器，正式接入时替换为 HTTP 客户端，页面不改变数据状态处理。

| 方法 | 路径 | 用途 | 成功结果 |
| --- | --- | --- | --- |
| `POST` | `/api/v1/auth/login` | 建立会话 | 当前用户和会话信息 |
| `POST` | `/api/v1/auth/logout` | 退出会话 | 204 或统一成功响应 |
| `GET` | `/api/v1/me` | 查询当前用户 | `User` |
| `GET` | `/api/v1/me/permissions` | 查询有效权限 | `{ permissionCodes: string[] }` |
| `GET` | `/api/v1/users` | 分页查询用户 | `{ items, total }` |
| `GET` | `/api/v1/users/{id}` | 查询用户详情 | `User` |
| `GET` | `/api/v1/departments` | 查询部门树 | `Department[]` |

员工号和手机号都是唯一业务标识。新增账号时前端先做重复提示，后端仍必须在数据库唯一约束和接口事务中再次校验。

### 6.1 统一错误处理

| 状态码 | 页面行为 |
| --- | --- |
| `400` / `422` | 显示字段或参数错误，保留用户输入 |
| `401` | 清除会话并跳转 `/login` |
| `403` | 显示无权访问，不伪造空数据 |
| `404` | 显示资源不存在，返回列表或重新选择 |
| `409` | 提示数据冲突，重新读取后让用户复核 |
| `5xx` / 网络错误 | 显示失败状态和“重新加载”按钮 |

## 7. 页面状态验收

用户和部门页面都必须覆盖以下状态：

| 状态 | 组件建议 | 说明 |
| --- | --- | --- |
| 加载中 | `el-skeleton` | 禁止在数据未返回时显示可误解的空表 |
| 正常有数据 | `el-table` / `el-tree` | 支持当前页面规定的查询和展示 |
| 成功但为空 | `el-empty` | 空数组是合法结果，不是请求失败 |
| 请求失败 | `el-result` + 重试按钮 | 保留可解释错误，不能提示保存成功 |

登录页覆盖提交中和凭证错误状态。按需求规格第 9 节不设账号类别（原“临时运维账号”在得到依据前不做），所有启用账号都能登录门户；岗位表示实际职位，不包含系统管理角色。部门管理员作为角色可以与其他角色共存，管理范围为所属部门。系统保留唯一预置超级管理员账号，不允许在新增表单授予超级管理员角色，也不允许停用此账号。成员 3 的页面接入时沿用这些约定。

## 8. 原型状态验证

开发环境的 mock API 支持通过 URL 参数稳定复现页面状态。先登录，再打开对应地址：

| 地址示例 | 预期状态 |
| --- | --- |
| `/users` 或 `/departments` | 正常数据 |
| `/users?demo=loading` | 骨架屏，约 1.8 秒后返回数据 |
| `/users?demo=empty` | `el-empty` 空数据 |
| `/users?demo=error` | `el-result` 错误页和“重新加载”按钮 |
| `/departments?demo=loading` | 部门树加载中 |
| `/departments?demo=empty` | 暂无部门数据 |
| `/departments?demo=error` | 部门加载失败 |

登录页可以输入错误密码验证凭证失败；登录按钮提交期间显示加载状态。恢复正常状态时删除 URL 中的 `?demo=...` 参数。
