# 成员3一期原型演示稿

建议用时5—10分钟。使用当前main的一套Vue原型，不需要打开早期独立HTML样例。[本次页面检查和截图](../testing/member3-stage1-acceptance.md)。

## 演示前

在仓库根目录安装并启动：

```sh
npm --prefix frontend ci
npm --prefix frontend run dev
```

打开终端显示的地址。已有部署时改用成员4交付的公网地址，路径相同。原型口令均为 `123456`，只是合成演示；真实后端口令来自部署配置。刷新会恢复模拟数据，现场修改不保存到数据库。每轮演示先刷新，待需要保存的截图完成后再刷新。

## 1. 门户与按钮权限（约1分钟）

1. 登录或右上角切换为普通员工 `SG000013`，展示门户只有5个系统、66个功能点，没有管理后台。
2. 打开 `/portal/f/f052` 考勤管理：查看、编辑可用且范围为本人；新增、审批、导出、删除置灰。
3. 解释：“没有查看权限的功能点不进入菜单；能查看也不代表拥有其他操作。前端只负责展示，服务器仍须逐请求鉴权。”
4. 直接访问 `/admin/catalog`，展示403及返回门户入口。

## 2. 我的权限与来源（约1分钟）

1. 打开“我的权限”，展示73条，全部64条、本人9条。
2. 搜索 ` HR:F052:EDIT `，只出现一项，显示本人范围、来源普通员工；大小写及首尾空格不影响结果。
3. 解释：“多个启用角色的权限取并集，同码范围取最大；不同权限码的范围独立。停用角色不会贡献有效权限。”
4. 切换无角色账号 `DEMO000103`，展示无权限空态；切回管理员 `admin`。

## 3. 角色管理（约1分钟）

1. 打开角色管理，指出6个内置角色不可删除，超级管理员不可停用。
2. 新建 `M3_DEMO`，名称“成员三演示角色”。名称空白不可保存，合法保存后可检索。
3. 点击用户数0，展示角色用户抽屉的空状态。关闭后点该角色“授权”。
4. 解释：“分配角色是把角色给用户；角色授权是配置角色拥有的权限。这两种集合不能混为一谈。”

## 4. 草稿、范围与整组保存（约2分钟）

1. 角色授权页搜索 `f010` 会议室预约，勾“编辑”。查看自动勾选，底部显示新增2条。
2. 编辑范围选“本部门”，查看保持“全部”，说明同一功能点不同操作可以有不同范围。
3. 清除搜索、翻页、再搜 `f010`，勾选和范围仍在。
4. 点击左侧“角色管理”，在离开提示中选择“继续编辑”，说明未保存草稿受保护。
5. 勾选“模拟保存中途失败”再保存：弹窗明确保存前集合不变，页面草稿保留。强调这是原型模拟，数据库事务由后端另验。
6. 确认弹窗，关闭失败模拟，重试保存；版本从1到2，差异归零。

## 5. 冲突与只读（约1分钟）

1. 再勾一个新操作，点“模拟另一管理员先保存”，随后保存。
2. 展示409冲突，解释：“旧版本不会覆盖先保存的结果，需要重新读取并复核，不能自动强行重试。”确认后重新加载。
3. 角色下拉选择超级管理员，展示授权只读、无保存入口。
4. 可选：切换公司领导，打开 `/admin/grants?role=R05`，展示因无修改权限而只读。

## 6. 资源目录与阶段边界（约1分钟）

1. 管理员打开资源目录，展示18系统、115模块、359功能点、2154条清单权限，目录只读。
2. 搜索 `hr:f046:edit`，展示员工台账及6个稳定操作码；打开CAT-03页签展示清单权限到 `rbac:*` 的映射。
3. 打开角色继承或职责约束，指明阶段二/三静态原型，页面操作不会保存，不作为一期后端能力。

## 演示结束与答辩要点

刷新页面恢复合成初始状态，或在角色管理删除本轮自建角色；不要在真实员工数据环境执行模拟演示。

- 我的交付是同一套Vue中的门户权限展示、角色与授权配置、资源目录，以及检查报告、截图和演示步骤。
- 已验证前端58项测试、生产构建和桌面浏览器流程；模拟失败、409和会话变化均有对应行为检查。
- 本轮没有操作服务器；部署后需在真实公网地址复查页面。前端原型、真实后端、数据库与外网验收的证据分别记录。
