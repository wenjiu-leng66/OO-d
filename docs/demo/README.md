# 一期演示准备

按 [检查前自测](../stage1/self-test.md) 先跑自动检查、真实HTTP及持久化，再填 [验证记录](../stage1/verification-record.md)。检查当天记录服务器URL、源码SHA、迁移版本、数据类型、演示账号角色和已知限制。

建议顺序：

1. 打开完整界面原型，切换超级管理员、领导、经理、员工与部门管理员，展示页面、按钮和范围。
2. 展示OpenAPI与rbac映射，说明原型和真实后端分别运行。
3. 用真实后端Cookie登录，验证首次改密、允许/拒绝、本人/部门范围。
4. 两会话演示授权下一请求生效、旧版本409、超级管理员/内置角色保护。
5. 展示服务器健康、数据库持久化重启、脱敏的自动化/导入结果。

演示原始数据应在受控环境中进行。公开录屏/截图不显示密码、Cookie、真实员工资料或环境文件；合成演示清楚标注。角色继承、约束、激活角色与日志只说明为后续阶段，不把静态按钮当作一期后端实现。
