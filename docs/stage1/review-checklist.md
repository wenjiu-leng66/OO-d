# 一期边界与风险检查清单

本页列“应检查的事项”，不是全部通过声明。执行者为每项记录输入、预期、实际、环境、源码 SHA、脱敏证据和责任人，结果写入 [验证记录](verification-record.md)。需求对应 [41 条追溯](requirement-coverage.md)，命令见 [自测步骤](self-test.md)。

## A. 验收顺序和证据一致

- 助教检查在老师预约前完成；确认候场、分组牌、预约及下午教室。每人准备可指向自己代码的一段讲解。
- 服务器源码 SHA、运行镜像、API 文件、测试报告是否是同一版本？不能用历史截图或旧 target 冒充本轮结果。
- 原型、真实后端、单元测试、H2整合、MySQL整合、全量导入、云服务器各自留证，不互相替代。
- Swagger 地址可打开后，还要真实登录并调用一条允许和一条拒绝接口；确认课程认可该 API 归档入口。
- 报告列行/分支/方法覆盖率、未覆盖代码、失败和待执行项；不只截绿色百分比。

## B. 登录、口令、会话

| 检查 | 预期 / 需说明的边界 |
| --- | --- |
| 工号和手机号登录 | 同一用户，不存在/停用/错误口令统一401及提示 |
| 首次/重置后未改密 | 仅本人信息、改密、退出，直接调其他接口403 |
| 旧口令错、新旧相同、长度边界、Unicode、长尾差异 | 明确拒绝或正确校验；不出现旧算法72字节截断误判 |
| 登录会话ID轮换、退出、重置、停用 | 固定会话攻击防护；旧 Cookie 下一请求应失效 |
| 两浏览器同时登录后其中一处改密 | 当前会话可用，其他持旧凭证会话失效；重新登录验证 |
| Cookie属性、过期、HTTPS | HttpOnly/SameSite；Secure与部署协议匹配；重启会话与数据持久化区分 |
| Origin允许/拒绝/缺失 | 现有代码仅检查已提供的来源，不是完整CSRF令牌方案；不能宣称抵御全部跨站请求 |

## C. 授权与范围

- 无角色可登录但无权限；未知码、缺授权、停用角色一律拒绝。
- 同码多角色取最大范围，不同码不互相放大；有edit不等于有read，授予非read动作必须同时给read。
- DEPT包含全部下级，不是仅一层；SELF只等于本人，不等于本部门。自建SELF管理角色需要单独测试。
- 查看ALL、编辑DEPT场景分别验证，不能从可见性推导可写性。
- 列表先裁剪范围再筛选/分页/统计；筛范围外部门不能泄露total或姓名。
- 直接篡改URL ID、部门ID、角色ID、JSON多余字段；范围外/不存在对象按契约拒绝，不泄露字段。
- 修改用户迁入部门与原目标都需检查；SELF不可创建其他账号。
- 部门管理员只能分配业务角色，不能授/撤管理角色或改角色授权；密码重置保护按后端实际规则检查ADMIN/DEPT_ADMIN账号。含管理授权的自建角色是否同样限制重置须另行确认，不能当作当前保证。
- 撤角色、停角色、改授权下一请求生效，不要求重新登录；前端缓存展示与服务端最终判定分开。

## D. 写入原子性和保护

| 场景 | 应检查的结果 |
| --- | --- |
| 两操作者GET同version后保存不同集合 | 一个成功，旧version409，成功集合不被覆盖 |
| 数据库写到一半抛错 | 授权集合和version都回滚；mock单测不能证明事务 |
| 并发分配角色和删除角色 | 固定顺序锁行，确认逻辑不能被穿透，不能产生孤立关系 |
| 空集合、重复ID、未知/停用角色、非法scope、未知/重复权限码 | 按真实接口契约校验，失败无部分写入 |
| 删除/停用自己、改自己角色、保护admin与内置角色 | 明确拒绝，账号仍可恢复管理 |
| 删除仍有用户的自建角色 | 无confirm拒绝；确认后关系清理、用户version更新 |
| 删除部门负责人 | FK置空、关联清理；不按姓名误删同名员工 |

## E. 参数、数据与界面

- 分页从1开始，page/pageSize最小、最大、0/负数/超大值、空页、筛选变化回首页；未知字段和非法ID不能变成500。
- 工号/角色码重复，电话为空与非空唯一，非法电话号码/邮箱/长度、中文及空白归一化，错误包络不暴露SQL或堆栈。
- 员工台账只能改phone/email；提交姓名、部门或空对象不应悄悄成功。
- 授权树父子勾选、取消read后的子动作、全选/全不选、跨分页草稿、409后刷新和失败回滚。
- 无角色、无数据、加载、请求失败与重试、403/404、首次改密路由优先、直接输入管理URL。
- 快速筛选/翻页/切换部门/身份；返回慢的旧响应不应覆盖新结果。Users/Ledger/Departments/Dashboard当前缺少一致的过期响应抑制，列为人工复核与后续改进项。
- 原型mock的角色成员范围、重复授权码及延时写入语义与后端有差异；页面成功不可据此判断后端安全通过。

## F. 导入、迁移与全量数据

- 导入器只生成SQL；TRUNCATE十表重建有破坏性，DDL不能依赖普通事务整体回滚。只在专用库操作，保留备份及恢复验证。
- Excel合并格、稀疏行、乱码/全角/尾空白、未知部门、同名负责人、缺工号、重复工号/电话、非法角色和循环/孤立组织分别核对。
- 总体退出成功不代表每行成功；逐项查看failed/unresolved/warnings和源表行列，不能跳过坏行后照常认定全量成功。
- 稳定系统/功能编码不能随排序改变；`--update-codes`在后续失败前也可能已经写编号表，须检查git diff。
- 原始111组织、10000员工+admin、18/115/359/2154与3549+6授权分账核对；合成39用户/16部门不能套用正式数量。
- 同输入两次比较业务快照，排除随机盐哈希/时间；负责人按用户ID关联，经理/副职/领导角色与scope按规则核对。
- V001是MySQL权威迁移；H2 schema由脚本生成。核对唯一/FK/CHECK拒绝，迁移、回滚、重建分开记录。

## G. 部署、性能与运维

- 容器健康、实际映射端口、数据库连接、依赖启动顺序、Nginx重解析后端地址；仅重建backend后接口仍可访问。
- `internal`是Compose网络名，当前driver=bridge且不是`internal:true`；只能陈述未映射数据库/Java主机端口，不声称完全隔绝外部网络。
- MySQL命名卷重建后数据保留；不带`down -v`。后端重启需重新登录不等于数据丢失；env改初始密码不重置已有用户。
- 公网只读GET的200/UP不证明鉴权、写入、MySQL持久化、服务器代码版本、备份恢复或高并发。
- 当前若干列表findAll后Java过滤，测全量响应及内存再决定SQL分页/索引；不把小样例或单次HTTP耗时当并发指标。
- 性能记录数据规模、部署拓扑、硬件、并发/发压模式、预热、样本数、p50/p95/p99、吞吐和错误率，并区分应用/数据库/客户端瓶颈。
- JavaEE商品JPA/AOP实验的JMeter/Prometheus/Swarm要求另行准备；RBAC仓库当前未配置这些组件，不把课程示例性能数字当本项目结果。

## 现场最小讲解闭环

每人至少选一个真实用例：说明需求ID和边界 → 指出模块及调用顺序 → 展示一个允许和一个拒绝测试 → 解释覆盖率未覆盖内容 → 说明部署或数据库实测还缺什么。发现问题登记并解释影响，不用原型占位或历史记录掩盖缺口。
