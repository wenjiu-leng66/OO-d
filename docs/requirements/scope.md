# 需求范围

状态：组内结论（2026-10-15，成员 1 用 grill-me 需求访谈整理，待组长确认）；3 个问题待老师确认。主责：组长；所有成员参与。

完整需求见 [需求规格说明书](req-spec.md)，每条结论的理由见 [需求访谈记录](grill-record.md)。

## 目标

管理市政公司的员工、部门、角色、应用功能资源与授权关系，验证基础 RBAC、角色层级、约束及不同编程思路。

## 范围

- 所有启用账号都能登录；门户按权限显示菜单，管理后台只对有管理权限的人显示。
- 部门组织展示（只读）、角色管理、资源目录（只读）与角色授权。
- 用户角色分配和撤销（整组替换并带版本号），后端逐个请求检查权限和数据范围。
- 角色层级（多继承、无环）与有效权限计算。
- 静态、动态职责分离和基数约束；会话中激活角色。
- 数据范围“全部 / 本部门 / 本人”，用员工台账一个真实业务演示不能被绕过。
- 面向功能和面向对象两套后端的对比，有效权限计算的函数式模块。

原权限清单的 18 个系统全部导入为资源目录，业务系统做占位页；只有“员工台账管理”做成真实业务（组内已定，见 [Q-01](questions.md)）。

## 确认结论

| 项目 | 确认结论 |
| --- | --- |
| 系统参与者 | 超级管理员（清单的系统管理员，只预置 `admin` 一个账号）、部门管理员（非清单角色，管本部门及下级）、公司领导、部门经理、项目经理、普通员工。见 [req-spec 2.2](req-spec.md#22-参与者与角色) |
| 必须演示的业务场景 | 登录后按权限生成菜单；员工台账的“本人 / 本部门”范围不能被绕过；分配与撤销角色、角色授权；继承与环路检查；互斥与基数约束；激活角色 |
| 管理员初始化与账号策略 | `admin` 唯一且不能授予他人；部门管理员由超级管理员任命；导入账号的初始密码在导入时指定、不进仓库，首次登录必须修改；不能停用或修改自己 |
| 可用约束规则 | 静态互斥、动态互斥、基数（角色人数上限、每人角色数上限）；样例用自建能力角色构造。是否有老师指定的约束待确认（Q-13） |
| 两种后端的共享边界 | 共享 OpenAPI 契约和同一套数据库结构（成员 1 的迁移），各连独立库实例，不共享业务代码。待老师确认（Q-02、Q-03） |
| 数据范围与角色合并规则 | 范围分全部 / 本部门（含下级）/ 本人；部门经理、项目经理的管理类操作限本部门，查看为全部；多角色取并集，同一权限码取最大范围 |

具体问题见 [问题清单](questions.md)。
