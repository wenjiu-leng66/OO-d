# API 约定草案

状态：第一版草案，待全组确认及后端联调。权威契约文件为 [OpenAPI](../../api/openapi.yaml)，已由成员 6 补充 RBAC0 最小接口，但仍无已实现 API 或真实联调结果。

## 协作规则

后端作者提出接口，前端确认交互需要，成员 6 维护统一性。正式开发前补齐字段、状态、错误码、必要权限与数据范围。

路径草案以 `/api/v1` 为前缀，数据格式 JSON；需要认证的身份由后端验证的会话取得。前端返回的权限只用于界面展示，不能成为后端信任的授权依据。

| 讨论用接口 | 目的 | 必须说明 |
| --- | --- | --- |
| POST `/auth/login` | 登录 | 凭证、会话建立、失败状态 |
| POST `/auth/logout` | 退出 | 旧会话怎样失效 |
| GET `/me` | 当前身份 | 可展示字段 |
| GET `/me/permissions` | 当前有效权限 | 激活角色、操作、范围 |
| GET `/users` | 分页查询 | 页码起点、大小上限、筛选、排序 |
| PUT `/users/{id}/roles` | 替换角色集合 | 不得误写成增量添加；约束与并发 |
| POST `/role-hierarchy` | 添加继承关系 | senior 继承 junior；是否多父及无环 |
| POST `/session/active-roles` | 设置激活角色 | 必须已获分配；检查 DSD |

上述 RBAC0 接口已形成第一版 OpenAPI 草案；角色层级和激活角色属于后续阶段，仍只用于讨论。DTO 的 ID 类型、日期格式、成功与失败包络、分页字段统一决定，不能前端一套、两后端各一套。

认证失败通常 401，无权限 403，参数、约束冲突等按统一约定选 400 / 422 / 409。权限码用稳定资源与操作标识，显示名称可以变化。

测试两种实现时使用等价独立数据库，比较业务结果和状态；非业务 ID 与时间戳可以规范化比较。修改接口同时更新契约、前端、后端、测试和相关设计图。
